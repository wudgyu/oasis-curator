# Oasis Curator API 参考手册

> 版本：v1.0　适用对象：平台集成开发者、运维人员

## 1. 接口总览

平台对外提供 REST API，所有接口以 /api 为前缀，统一使用 JSON 作为请求与响应格式。受保护接口需要在请求头中携带 JWT 令牌。

下表列出文档与问答相关的核心接口：

| 方法 | 路径 | 说明 | 所需权限 |
| --- | --- | --- | --- |
| POST | /api/documents | 上传文档并完成解析、切分、向量化入库 | admin / manager |
| GET | /api/documents | 分页列出当前租户的文档 | 全部角色 |
| DELETE | /api/documents/{id} | 删除文档及其全部向量 | admin / manager |
| GET | /api/documents/search | 语义检索文本块 | 全部角色 |
| POST | /api/qa/ask | 提交问题并返回带引用的答案 | 全部角色 |
| GET | /api/qa/conversations | 查询当前用户的会话列表 | 全部角色 |

## 2. 上传参数说明

上传接口使用 multipart 表单提交，参数如下：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| file | 文件 | 是 | PDF、Word、TXT 或 Markdown 文档，单文件不超过 50 兆字节 |
| strategy | 字符串 | 否 | 切分策略，可选 paragraphs 或 chars，默认 paragraphs |
| visibility | 字符串 | 否 | 文档可见性，可选 tenant、private、roles，默认 tenant |
| allowed_roles | 字符串 | 否 | 当 visibility 为 roles 时生效，多个角色用逗号分隔 |

文档上传后立即完成向量化，无需额外的索引构建步骤，通常在三到十秒内返回结果。

## 3. 错误码对照

接口调用失败时返回标准 HTTP 状态码与错误信息，常见错误码如下：

| 状态码 | 含义 | 典型场景 |
| --- | --- | --- |
| 400 | 请求参数错误 | 上传了不支持的文档格式，或解析结果为空 |
| 401 | 未认证 | 未携带令牌，或令牌已过期 |
| 403 | 无权限 | 只读角色尝试上传或删除文档 |
| 404 | 资源不存在 | 删除的文档不存在，或不属于当前租户 |
| 409 | 资源冲突 | 同名角色编码已存在 |
| 422 | 参数校验失败 | 缺失必填字段，或字段格式不合法 |
| 500 | 服务内部错误 | 向量库不可达，或模型服务调用失败 |

## 4. 配额与限额

不同套餐的租户享有不同配额，超出配额时接口返回 429 状态码：

| 套餐 | 文档数量上限 | 单文件大小上限 | 每日问答次数 | 并发请求数 |
| --- | --- | --- | --- | --- |
| basic | 100 篇 | 20 兆字节 | 200 次 | 2 |
| pro | 1000 篇 | 50 兆字节 | 2000 次 | 8 |
| enterprise | 不限 | 200 兆字节 | 不限 | 32 |

配额统计按自然日重置，重置时间为每日零时。

## 5. 模型配置项

平台支持通过环境变量切换模型与部署模式，关键配置项如下：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| LLM_DEFAULT_PROVIDER | deepseek | 默认大模型供应商，可选 deepseek 或 kimi |
| EMBEDDING_PROVIDER | auto | 向量化模型选择，auto 表示按优先级自动选择 |
| ZHIPU_EMBEDDING_MODEL | embedding-2 | 云端向量化模型名称 |
| OLLAMA_EMBED_MODEL | bge-m3 | 离线模式使用的本地向量化模型 |
| DEPLOY_MODE | cloud | 部署模式，可选 cloud 或 offline |
| CHROMA_PORT | 18000 | 向量库服务监听端口 |

修改向量化模型后必须重建向量索引并重新导入文档，否则新旧向量维度不一致会导致检索失败。

## 6. 角色权限矩阵

平台内置四类角色，权限范围如下表所示：

| 功能 | admin | manager | auditor | employee |
| --- | --- | --- | --- | --- |
| 管理租户与用户 | 是 | 否 | 否 | 否 |
| 上传与删除文档 | 是 | 是 | 否 | 否 |
| 检索与问答 | 是 | 是 | 是 | 是 |
| 查看本组织数据 | 是 | 是 | 是 | 是 |
| 查看子组织数据 | 是 | 是 | 是 | 否 |
| 生成 IAM 权限配置 | 是 | 否 | 否 | 否 |

manager 的数据范围为所在组织及其全部子组织，auditor 与 manager 相同但仅有只读权限，employee 仅能访问所在组织的数据。

## 7. 调用示例

上传文档的调用示例：使用 curl 以 multipart 方式提交文件，请求头中携带令牌与上下文租户标识。服务返回文档标识、解析出的字符数、页数与切分出的文本块数量。

检索调用的示例：以查询参数 q 提交检索问题，可选参数 top_k 控制返回条数，默认返回五条。返回结果按相似度降序排列，每条结果包含文本内容、相似度分数、来源文件名与段序号。

问答调用的示例：以 JSON 请求体提交问题，响应包含最终答案、引用来源列表与重排序后的候选块信息。答案中的引用标注格式为方括号包裹的来源说明，可直接映射到检索结果中的具体文本块。
